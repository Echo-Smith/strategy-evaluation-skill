# WritingAgentBench 方法

## 核心原则

1. 冻结数据集、候选配置和 runner 后再比较。
2. Development 用于调优，Holdout 用于决策，两者不得混用。
3. 五项 Rubric 只接受 1—5 分；确定性规则进入 checks。
4. 硬失败优先于平均分。
5. 模型评审只能作为预检或独立评审者，不能替代人工仲裁。
6. 未观测到的用量、成本或用户行为明确标记 unavailable/unknown。

## 五项 Rubric

| 维度 | 关注点 |
| --- | --- |
| 任务符合度 | 是否完成正确任务并满足显式约束 |
| 事实与来源忠实度 | 是否可核验，是否保留状态、数字、人物和原意 |
| 结构与论证 | 层次、过渡、论点和论据是否成立 |
| 风格一致性 | 是否符合已声明的项目或用户风格，是否漂移 |
| 可直接使用程度 | 是否可以安全直接使用，人工修改范围多大 |

默认通过条件：加权总分不低于 80；任务符合度和事实忠实度均不低于 4；不存在硬失败。

## 标准流程

1. 定义问题、候选策略、主指标和晋级门槛。
2. 冻结 suite、case、来源 fixture、Prompt、Memory、模型、代码和工具配置。
3. 运行确定性 checks 和真实产品链路。
4. 生成不含候选身份和运行元数据的盲评材料。
5. 完成独立评审、分歧识别和人工仲裁。
6. 汇总通过率、维度分、硬失败、接受、修改负担、延迟、成本状态和工具失败。
7. 在独立 Holdout 上复跑候选。
8. 形成 release decision、回滚条件和新增回归样本。

## Badcase

先记录可观察症状，再结合 Trace 判断主根因：输入、检索、Prompt、Memory、工具、模型或交互。只有在输入、材料、Prompt、Memory 和工具均正确完整时，才把问题归为模型。

## 报告边界

公开报告包含协议版本、覆盖分布、聚合指标、脱敏示例和决策理由。私有来源全文、用户原始输入、内部 Prompt、凭证和可还原 Trace 不进入公开产物。
