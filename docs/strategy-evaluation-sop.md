# 笔润智谈策略评测 SOP

## 适用范围

当需要比较新的 Prompt、Memory、检索、工具或交互策略时，按本 SOP 执行。目标不是证明某个模型“永远更好”，而是用同一批任务、同一套标准和真实用户反馈，判断策略是否值得进入候选版本。

## 一、评测流程总览

```text
定义数据契约
  → 固定 Rubric 与 Badcase 分类
  → 生成并冻结评测集/来源材料
  → 运行成对策略实验
  → 生成中文盲评 Excel
  → 人工评分与真实用户接受反馈
  → 导入、校验、汇总报告
  → 冻结候选版本
  → 运行 Holdout
  → 上线、继续迭代或回滚
```

## 二、建立评测集

每条案例至少包含：

- 任务类型：选题、写作、润色、查重、异常输入；
- 用户输入；
- 预期行为；
- 冻结知识库/来源材料；
- 难度等级；
- 风险标签；
- 对应 Rubric 和硬失败规则。

正式集分为两部分：

- 开发集：48 对 / 96 个输出，用于筛选策略和发现 Badcase；
- Holdout：32 对 / 64 个输出，用于验证策略能否泛化。

Holdout 在候选版本冻结后才解封，不能根据 Holdout 结果回头修改策略再重新解释结果。

## 三、评分标准

每个输出按 1—5 分评价：

1. 任务符合度：是否完成任务、遵守边界和字数要求；
2. 事实可核验性：事实是否有依据，是否清楚区分事实、推断和假设；
3. 结构与推理：层次、论证和结论是否清楚；
4. 风格一致性：是否符合项目写作规范和已确认的个人风格；
5. 可直接使用程度：是否可以直接交付，或需要多大修改。

每个输出还要填写：

- 接受档位：可直接使用、轻微修改后使用、大幅修改后使用、拒绝使用；
- 是否硬失败；
- 硬失败类型；
- 主要根因和次要根因；
- 修改量估计；
- 评分依据/备注。

硬失败不能被其他维度的高分抵消，例如编造关键事实、把未来事件写成已完成、改变原意或泄露隐私。

## 四、Badcase 根因

统一使用七类：

- 输入：信息缺失、冲突或任务本身不可执行；
- 检索：漏召回、错召回、来源质量不足；
- Prompt：约束、优先级或证据闸门设计不当；
- Memory：旧偏好、错误记忆或记忆冲突；
- 工具：外部工具调用、解析或执行失败；
- 模型：上下文已足够但仍生成或推理错误；
- 交互：应该追问、确认、拒绝或降级时没有处理。

## 五、成对策略实验

每个案例生成方案甲和方案乙，只改变一个策略变量。例如：

- 通用提示词 vs 结构化个人风格记忆；
- 无来源约束 vs 来源证据闸门；
- 一次生成 vs 研究—写作—审校流程。

方案甲/乙会随机化，评测者不能根据标签猜测策略身份。

## 六、Excel 填写方式

评测者只填写黄色单元格：

### 方案评分

逐条阅读用户输入、冻结材料和模型输出，然后填写五项分数、接受档位、硬失败、根因、修改量和备注。

### 成对选择

完成方案评分后，比较同一案例的方案甲/乙，填写：

- 更优方案；
- 判断依据；
- 真实用户接受甲；
- 真实用户接受乙；
- 备注。

“评测者接受”与“真实用户接受”必须分开。没有真实用户反馈时选择“未收集”，不能猜测。

## 七、报告指标

导入 Excel 后自动计算：

- 通过率；
- 五项 Rubric 均值和加权总分；
- 评测者接受率；
- 真实用户接受率；
- 平均修改量；
- 硬失败率；
- 成对胜负；
- 七类根因分布；
- 实验组相对对照组的变化。

Excel 中的 `50` 等填充噪声不得被当作根因、备注或硬失败类型；导入器应先清理并记录处理规则。

## 八、候选冻结与 Holdout

候选冻结时记录以下内容的版本或 SHA-256：

- 评测案例和来源材料；
- Prompt 和 Memory 规则；
- 模型配置；
- 实验运行器；
- 报告生成器。

冻结后运行 Holdout，Holdout 只允许评分和报告，不允许调参。

## 九、上线条件

建议同时满足：

- Holdout 通过率不低于基线；
- 硬失败率不明显上升；
- 真实用户接受率不下降；
- 平均修改量不恶化；
- 高风险案例全部满足硬门槛；
- 回归测试和评测资产校验全部通过。

任一关键条件不满足，就保持候选状态、继续迭代或回滚，不把开发集结果直接写成上线结论。

## 十、知识库来源路由专项回归

用户明确说“用乐享知识库”“用知识库”“用 IMA 知识库”时，必须检查：

1. 是否选择了正确 provider；
2. 是否只调用指定知识库；
3. 是否没有调用全网搜索或补充联网搜索；
4. SSE `kb` 事件是否带 provider；
5. Agent trace 是否记录来源决策。

这类“明确来源选择”优先使用确定性路由守卫，不使用开放式 ReAct。只有在“知识库无结果后是否征得用户同意再联网”这类多步授权场景，才考虑受约束的 ReAct。

IMA 和乐享是两个可并存的 provider，不需要二选一删除其中一个。`KNOWLEDGE_PROVIDER` 只决定用户说“知识库”时的默认 provider：设置为 `ima` 即默认走 IMA，设置为 `lexiang` 即默认走乐享；用户明确说“IMA”或“乐享”时会覆盖默认值。

## 十一、落盘产物

每次评测至少保留：

- 评测集和来源清单；
- 候选冻结记录；
- 中文盲评 Excel；
- 评测者导入数据；
- JSON/Markdown 报告；
- 回归测试结果；
- 本次经验复盘。
